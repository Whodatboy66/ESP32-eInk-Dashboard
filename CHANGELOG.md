# Changelog

One line per change that reaches the devices or the build. Stages: [docs/IMPLEMENTATION_PLAN.md](docs/IMPLEMENTATION_PLAN.md).
Versions: `FW_VERSION` in [configure.h](configure.h) (an integer `FW_BUILD` follows in stage 1).

| Version | Stage | Change |
|---|---|---|
| .63 + fork | 0 | `sketch.yaml` profiles fixed; `tools/epd_test`; docs |
| .63 + fork | 0 | Zigbee removed; CI builds the `sketch.yaml` profiles on every push with a size check and host tests; button: pull-down, fault limit, setup on release, BOOT backup |
| .63 + fork | 0 | Repository layout: short README, user manual in `docs/USER_GUIDE.md`, screenshots in `docs/images/`, font converter in `tools/`, this changelog |
| .64 | 1 (part 1) | Over-the-air updates from GitHub releases: A/B partition table (one USB flash needed), `FW_BUILD`, update check at night with "Install updates automatically" (or "Update available" in the status bar), double tap = info and update screen with confirm tap, setup page "Check for updates now", battery guard (30 % or USB), SHA-256 check, rollback, update screens; CI release job with `manifest.json`. Not signed yet |
| .66 | 1 | Signed release manifests (ECDSA P-256, secret `OTA_SIGNING_KEY`; unsigned or altered releases are rejected), stable/beta update channel (setup page), display id and settings-schema version checked before an install; CI reads them out of the image. Must be released on stable (64/65 devices don't know channels). Timezone: names like `CET` / `Europe/Berlin` become a POSIX rule (a bare `CET` was UTC, 1 h off), invalid ones are refused. Manual workflow "OTA test release" for broken-update tests on the beta channel. Setup page: the saved Wi-Fi network is pre-selected (saving the page used to switch to the first scanned network and lose Wi-Fi) |
| .67 | 2 | Firmware split into modules (`src/`); every HTTPS request checks the server certificate (Bambu LAN excepted, local addresses only); secrets masked in the log; setup page checks input before saving (says what to fix), turns `webcal://` and `http://` calendar links into `https://`, accepts printer names that resolve to a local address; factory reset (setup page, or `factory-reset` on the serial console); fonts stored once (17 KB smaller). No visible change on the screen |
| .68 | 3 | Layouts: Classic (unchanged), Planner, Minimal, Technical, chosen on the setup page together with 12/24 h and which widgets are shown; switched-off widgets leave no gap; widgets adapt to their size and are clipped to their place; a failed download is retried after 2, 4, 8 and 16 minutes instead of waiting a full interval, and data that is too old gets an "old" badge. Settings schema 2 |
| .69 | 1 (fix) | OTA test builds: a device left on a test build (90001+) takes any regular release again (it called every release "Up to date"), and a test build is never confirmed by the button, setup mode or the update screen, so the hang / crash tests always roll back |
| .70 | 4 | Personal widgets: tasks (due date, priority, done), a note, birthdays (typed in, and from a birthday calendar link); stored on the device's user-data partition (kept through updates, erased by a factory reset); new layout "Personal"; JSON API for them in setup mode (`docs/SETUP_API.md`). The screen font gets umlauts, ß, € and `! " & ' ( ) ; @ [ ]`. The time zone is applied at every wake (it was set only by the clock widget) |
| .71 | 5 | New setup app (served by the device, no internet needed; Paper look, tabs Home / Screen / Data / Device, guided first start): layout editor with structures, split / merge of boxes, a widget per box, clock and status bar optional, sketch and exact preview from the device; a layout change is shown without a restart. Checks for Wi-Fi password, calendar links and weather place. The setup hotspot has a per-device password (shown on the screen with a Wi-Fi QR code). Edit mode on the home network (4-second hold with working Wi-Fi): address, QR code and a 6-digit code on the screen, 10 minutes. New setting: device name (`<name>.local`). Settings schema 3. The old page stays at `/basic` for now. Battery: a reading below 3.0 V (no battery, or not measurable) counts as USB power: updates are no longer refused as "battery too low", the top bar shows `USB` |
| .72 | 5 (diagnostics) | Setup app, Device tab "Diagnostics": the recent log (also as a download), the battery voltage once an hour for the last 7 days as a chart, and the state of each service (last success, failures, next retry). Every log line (formerly some only on USB) goes through one logger: on USB as before, and stored on the device after wakes that did something (Wi-Fi, a problem, a full refresh, setup mode); the quiet once-a-minute clock wakes write nothing. A factory reset erases the log |
| .73 | 5 (fixes from the device test) | After saving settings the device comes back in the same mode (hotspot, or edit mode with the same code and session) instead of ending setup mode, so the app reconnects. Printer: status over MQTT only when address, serial number and access code are set (MakerWorld stats alone work without it); a printer that doesn't answer is asked again after 10, 20, 40, then 60 minutes instead of every 10 minutes, 2 short attempts instead of up to 5. Printer connection attempts time out after 5 s (were 30 s each). Time: the time sync no longer resets the time zone to UTC (log times, "today" and edit mode ran on UTC after every Wi-Fi connect). Log: "storage mounted" line; the firmware version also at the end of every wake (a USB monitor misses the first lines after a deep-sleep wake); "no battery measured" instead of "0 %" |
| .74 | 5 (fix) | Log: the first lines of each wake (wake reason, pins) are in local time too (the time zone is applied while the settings load); the button wake is named as such. Battery in the setup app: the last reading taken with Wi-Fi off (with the radio on the voltage sags: the app showed 56 % while the dashboard measured 68 %) |
| .75 | 6 (part 1) | Power: the clock refresh interval is a setting (1, 2, 5, 10, 15 or 30 minutes; wakes on round times), with the estimated battery life for each choice in the setup app; night quiet hours (default 23:00-06:00, configurable, can be switched off): no updates, the status bar says "Night until 06:00", a tap shows the current dashboard, full refresh in the morning; battery saver below 20 % (every 15 min, "Battery saver" in the status bar, off again above 30 % or on a computer's USB); below 5 % a "please charge" screen and only the button wakes it. The night update check runs from 03:00 until noon (with quiet hours over 03:00: at their end). Battery capacity setting for the estimate |

Done tasks remember when they were ticked off and are deleted after 30 days. The exact preview uses the app's current 12 / 24-hour choice. App: ready-made layouts in their own row, the preview text no longer claims sample data |
| .77 | 6 (fixes from the device test) | Top bar: the battery percent right of the battery icon, the date alone on the left. Weather: the weekday above each icon (where there is room: grid layouts).
